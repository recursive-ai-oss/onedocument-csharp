# Workbook calculation

Namespace `RecursiveAI.OneDocument.Spreadsheets.Calc`, in the `.Spreadsheets` package, over the evaluator in `calc.md`. Entry points: `Workbook.Recalculate`, `Workbook.RecalculateAll`, `Cell.SetDynamicArrayFormula`, and `onedocument recalc`.

Excel is the specification. Statements below marked *(pending the Excel check)* are first readings: the workbooks that settle them are generated by `tools/CalcSweep` (`gen`), have been run through the evaluator here, and are to be recalculated by Excel and compared with `CalcSweep compare` at the release gate; none of them has been compared with Excel yet.

## When it runs

Opening never calculates. `Recalculate()` is the explicit command and calculates whatever the calculation mode says: a workbook set to manual stays manual (the `calcPr` is not touched) and the call is "calculate now". Edits made through `Cell` (values, formulas, clearing) are noticed; a plain `Cell.Formula` edit still sets `fullCalcOnLoad` as before and nothing is calculated until you ask.

The first call builds the dependency graph and calculates everything. Later calls calculate the formulas an edit made dirty, plus the volatile and the run-time-reference ones. `RecalcOptions.Full` (or `RecalculateAll`) calculates everything.

## The graph

One node per formula cell (shared formulas are translated from their anchor; data tables are left alone). The reverse index maps a cell to the formulas that read it:

- a block of up to 16 cells is stored as one entry per cell; a bigger block as one entry per column (rows `first..last`), found by a binary search and a running maximum; a block wider than 256 columns sits in a short list. `SUM(A1:A100000)` is one entry.
- defined names are expanded: a formula using a name depends on what the name's formula reads (a name holding a lambda reads nothing, its calls' arguments are walked). Sheet-scoped names hide workbook names on their sheet.
- table references become areas at build time; `[#This Row]` is the cell on the formula's own row.
- 3-D references depend on the cell on every sheet between the two (workbook order, either way round).
- whole-row and whole-column references are blocks; when read they are clipped to the sheet's used extent (`ICalcResolver.ClipArea`), so `SUM(A:A)` reads the used rows only. `ROWS(A:A)` still answers 1,048,576 because it asks the reference, not the values; a function that inspects the *shape of the array* made from a whole column sees the used extent.
- external references are `#REF!` (default-deny) and add no edges.

A formula edit, a sheet/name/table change or a different function registry rebuilds the graph on the next call (a pass over the formulas, no evaluation); a value edit costs only its dependents. After a rebuild only the edited cells' dependents are recalculated, unless a sheet, name or table changed, which recalculates everything.

## Levels and threads

Formulas whose inputs are all finished form a level. A level runs on all the cores (`RecalcOptions.MaxDegreeOfParallelism`, default one per processor; levels smaller than `ParallelThreshold` run on the calling thread); results are written to the grid afterwards, sequentially, in cell order. Formulas on one level never read each other, so the answers do not depend on the thread count (tested at 1, 2 and 8). Volatile functions give different answers per call by nature.

A formula that builds references at run time (a function marked `FunctionTraits.DynamicReference`: `INDIRECT`, `OFFSET`) cannot name its inputs in advance. Such formulas run alone, after the other formulas of their level, and when one reads a formula cell that has not been calculated yet, that cell is calculated first, inline (nesting limit 200). The dynamic ones and the volatile ones are dirty on every call.

## Circular references

When no formula is ready but some are waiting, what is left is cycles and the formulas below them. The formulas on a cycle (strongly connected sets, and a formula that reads itself) get the value 0 and a `calc.circular-reference` defect; the formulas below them then calculate from those zeros. Iterative calculation is not implemented. *(pending the Excel check: that Excel shows 0 for every cell on the cycle and calculates the others from it; workbook `circular`)*

## Dynamic arrays and spills

A formula is a dynamic array when it is stored as an array formula (`t="array"`) on a cell with the dynamic-array metadata (`cm`, [MS-XLSX] CT_DynamicArrayProperties). `Cell.SetDynamicArrayFormula` writes that form (and adds `xl/metadata.xml` when the workbook has none; a workbook whose metadata part has no dynamic-array entry is refused). Array formulas without `cm` are legacy: they fill the range they name and pad a smaller result with `#N/A`. Plain formulas get implicit intersection.

A dynamic result larger than one cell is written into the grid: the anchor keeps the formula and `ref` (the spilled range), the other cells hold plain cached values, which is how Excel stores a spill. It is `#SPILL!` (and `ref` shrinks to the anchor) when a cell in the range other than the formula's own earlier spill holds a value or formula, when it touches a merged range or a table, or when it runs past the last row or column. A `#SPILL!` formula is tried again on every call, and so is a formula whose spill range was edited. If two spills overlap, the one calculated first (cell order within a level, lower levels first) wins. `A1#` reads the spill range of the anchor at `A1` (`#REF!` when `A1` is not a dynamic-array formula), and formulas that read spilled cells follow a changed spill in a further pass (at most 8). *(pending the Excel check: every blocker kind, the overlap rule, `A1#` on a one-cell result; workbooks `spill-*`)*

## After a calculation

Cached values in the store are updated; formulas whose result did not change are not rewritten. A text result is kept as a formula string result. Saving writes them as it writes any edit. `fullCalcOnLoad` and the calculation chain are handled as they are for any formula edit.

If a call is cancelled, some cells hold new values and some old ones; call again to finish.

## Tools

`onedocument recalc <workbook> [-o out] [--full] [--threads n]` calculates and saves (in place when no `-o`). `tools/CalcSweep PATH...` is the cached-value harness: it remembers every formula's stored value, calculates everything, and compares (numbers at 15 significant digits, text, booleans and errors exactly), classifying each difference as `unimplemented` (the formula calls a function the registry lacks), `external`, `downstream-or-bug` (the workbook has an unimplemented function elsewhere) or `bug`. The figure to quote is matches over the formulas whose functions are all implemented. `CalcSweep gen DIR` writes the Excel test workbooks, `CalcSweep compare ANSWERS` compares them with the oracle's cells-mode answers.

## Not here yet

Iterative calculation, data tables, Goal Seek, external-link resolution, pivot refresh, `NOW`/`TODAY` clocks, and the function families beyond the evaluator's seed set (a formula calling a missing function evaluates to `#NAME?`).

## Deviations

- A whole-column reference as an array has the used extent's shape (above).
- A relative reference inside a defined name is read as written, from cell A1.
